## 3. 架构变化

- **进程生命周期层**：`platform_proc.py` 提供 PID + 创建时间身份、存活判断、进程树优雅/强制终止；Windows 使用 `GetProcessTimes`/`taskkill`，Linux 使用 `/proc`/进程组，其他 POSIX 使用 `ps`。
- **Engine 租约**：`engine_locks` 单行 CAS 租约，`start/resume/recover` 需要租约；只读查询不需要；异常退出后租约到期可接管。
- **Agent 协议**：`agent_protocol.py` 定义运行中动态决策请求文件；决策持久化后节点进入 WAITING_HUMAN。
- **调度**：WAITING_HUMAN 的下游节点为 BLOCKED；决策完成后重新计算并回到 READY/PENDING。
- **WCP**：已完成节点输出提取为可交接文本；自定义 Prompt 也会追加 Continuation Context。
- **Adapter**：Claude CLI Prompt 通过 stdin 传入，规避 Windows 命令行长度限制；CLI 输出强制 UTF-8。
- **取消**：先终止 Agent 进程树，再关闭决策、取消节点、进入 CANCELLED；迟到结果不会覆盖终态。

## 8. 最终真实 E2E 证据

测试：`tests/integration/test_p05_final_e2e.py`，`1 passed in 70.70s`。

流程：

1. 创建 3 节点 DAG：research → handoff → finalize。
2. 独立 CLI 进程启动 Engine，真实 Claude 执行 research。
3. Agent Run 进入 RUNNING 后强制 kill Engine 进程，并终止 Agent 进程树。
4. 新 Engine 进程恢复：租约过期接管，Recovery 检测进程死亡，research `INTERRUPTED` → 重试。
5. research 第二次真实 Run 成功，Checkpoint 保存。
6. handoff 动态请求人工决策 → Workflow `WAITING_HUMAN`，finalize `BLOCKED`。
7. CLI resolve（独立进程）→ CLI resume（独立进程）。
8. handoff 第二个 Agent Run 从 Continuation Context 取得 token，写 `handoff.txt`；finalize 写 `final.txt`。
9. Verifier 通过，Workflow `COMPLETED`。

实际状态：

| 项目 | 值 |
|------|-----|
| Workflow | `COMPLETED` |
| Nodes | research attempts=2 SUCCEEDED；handoff attempts=2 SUCCEEDED；finalize attempts=1 SUCCEEDED |
| Agent Runs | research INTERRUPTED → SUCCEEDED；handoff SUCCEEDED ×2；finalize SUCCEEDED |
| Decision | handoff RESOLVED approve |
| Checkpoints | 9 |
| Retry | research attempt 2 |
| 关键事件 | `agent.process_started`、`node.interrupted`、`node.retry_scheduled`、`workflow.recovered`、`human_decision.agent_requested`、`human_decision.resolved`、`workflow.completed` |
| 文件 | `handoff.txt` == research token；`final.txt` == `FINAL-OK` |
| Crash 阶段 | Workflow RUNNING，research RUNNING，Agent Run RUNNING |
| Waiting 阶段 | Workflow WAITING_HUMAN，handoff WAITING_HUMAN，finalize BLOCKED |

## 9. 故障恢复验证证据

- Engine 强制退出：`test_engine_crash_then_restart_recovers`。
- Agent 存活时恢复不重复启动：`test_live_agent_survives_engine_crash_and_recovery_waits`。
- Agent 死亡/孤儿：Recovery 标记 INTERRUPTED 并按策略重试。
- 租约：并发 acquire 仅一个成功；持有进程死亡后到期接管。
- Checkpoint 写入失败不被吞掉。
- 终态后重复 resume 不重跑已完成节点。
- 外部修改工作目录不影响已完成状态。

## 11. 已知限制

| 限制 | 说明 |
|------|------|
| 单机模型 | SQLite 租约、PID 身份仅本机有效；不支持跨主机/分布式调度 |
| 无独立 Agent 监督进程 | Engine 死亡而 Agent 存活时，Recovery 等待其退出后重试；依赖幂等键避免重复副作用 |
| 真实测试默认跳过 | 需要本机 Claude CLI 认证与网络，普通 CI 不执行 |
| 动态决策协议 | 基于工作目录文件，Agent 必须遵循 Prompt；未接入 MCP/通知 Provider |
| 输出体积 | 单节点交接输出截断 4000 字符，Prompt 上下文上限 32000 字符 |
| Windows 优雅终止 | 依赖 `taskkill`，失败回退强制终止 |
| 未推送 | 本地提交，未执行 `git push` |
