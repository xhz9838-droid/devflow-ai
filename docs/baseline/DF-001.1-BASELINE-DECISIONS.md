## 二、task_close 策略统一

### 2.1 用户授权原文

> - 验收通过后允许自动 finish/done
> - 禅道任务状态为 done、验收通过、交付物和必要记录齐备后，允许自动 close
> - 保留幂等、状态读回、操作记录和失败处理
> - 不需要每次向用户请求 finish 或 close 确认
> - 不允许删除禅道任务

### 2.2 三个版本对照

| 策略项 | dev（旧版） | dist（当前） | 全局（快照） | 用户授权 |
|--------|------------|-------------|-------------|---------|
| task_finish | 门禁后可自动 | 门禁后自动 | 门禁后自动 | ✅ 自动 |
| task_close | **始终禁止自动** | 条件满足后自动 | 条件满足后自动 | ✅ 自动 |
| 删除任务 | 禁止 | 禁止（close ≠ delete） | 禁止 | ✅ 禁止 |
| 读回确认 | 有 | 有 | 有 | ✅ 保留 |
| 幂等 | 有 | 有 | 有 | ✅ 保留 |
| 不满足暂缓 | 无 | 有 | 无 | ✅ 保留 |

**分析**：
- dist 和全局的 `task_close` 策略与用户最新授权**一致**
- dev 的"始终禁止自动"是**旧版策略**，已被用户明确废弃
- dist 的 `approval-policy.md` 已将审批边界表更新为"完成业务任务 ❌（门禁后自动）"和"关闭业务任务 ❌（关闭条件满足后自动）"
- dist 的 `workflow-lifecycle.md` 已更新状态流转授权描述

### 2.3 需要修改的文件（在 DevFlow AI 基线建立时）

| 文件 | 当前状态 | 需要的操作 |
|------|----------|-----------|
| `skill/SKILL.md` 规则 8 | dev 旧版：`task_close` 始终禁止 | 替换为 dist/用户授权版本 |
| `skill/references/approval-policy.md` | dev 旧版：关闭业务任务 ✅ 严禁自动 | 替换为 dist 版本（finish→done ❌ 门禁后自动，close→closed ❌ 条件满足后自动） |
| `skill/references/workflow-lifecycle.md` | dev 旧版：始终禁止自动执行 | 替换为 dist 版本（关闭条件满足后自动执行 + 暂缓机制） |
| `config/workflow.yaml` | 使用 `zentao.allow_finish` / `zentao.allow_close` 配置 | 保留配置机制，默认改为 `auto_after_gate` |

### 2.4 DevFlow AI task_close 最终规则

```
1. task_finish（doing → done）：
   Verifier 门禁通过后自动执行，写入后读回禅道状态确认。
   
2. task_close（done → closed）：
   关闭条件全部满足后自动执行：
   - 禅道任务状态为 done
   - Verifier 验收通过
   - 最终报告已生成
   - 必要交付物已提交
   - 待处理 Human Decision 已全部解决
   不满足任一条件 → 暂缓关闭，记录原因到 audit.jsonl。
   写入后必须读回确认。close 是状态流转，不是删除任务。
   
3. 幂等保护：
   - finish：已 done 直接跳过
   - close：已 closed 直接跳过
   
4. 审计：
   - 每次操作记录前后状态、结果、失败原因到 audit.jsonl
   - 读回不匹配 → 记录并报告，不盲重试
```

## 五、zentao 模块归属

### 5.1 当前实现

dev 中 `zentao/` 模块仅含一个文件：`zentao/_shared/client/tasks.py`（281 行）。

该文件是一个 `TasksMixin` 类，提供禅道任务只读查询：

- 依赖全局 Skill 安装的 `zentao._shared.client_api.ZenTaoClient` 和 `zentao._shared.user_resolver.extract_account`

**实际运行时**：`zt.py` 从 `~/.claude/skills/zentao/_shared/` 导入 `ZenTaoClient`，而非本地的 `zentao/` 模块。本地 `tasks.py` 的 `from .response import _extract_list` 相对导入表明它原本是 `ZenTaoClient` 源码树的一部分。

### 5.2 调用关系

```
scripts/zt.py
  → from zentao._shared.client_api import ZenTaoClient, load_config  (全局 Skill)
  → from zentao._shared.user_resolver import extract_account          (全局 Skill)

agent-manager/zentao_reporter.py
  → 通过 CLI 调用 zt.py（间接使用 ZenTaoClient）

scripts/project_register.py
  → 读取 config 中 zentao.project_id（不 import zentao 模块）

scripts/project_resolver.py
  → 读取 config 中 zentao.project_id / zentao.product_ids
```

### 5.3 归属判断

| 组件 | 归属 | 建议 |
|------|------|------|
| `zentao/_shared/client/tasks.py` | 禅道专属 | 归入 DevFlow AI 的 ZenTao TaskProvider 实现 |
| `zt.py` 中 finish/close/progress 逻辑 | 禅道专属 | 核心流转逻辑归入 ZenTao Reporter Provider |
| `zentao_reporter.py` | 禅道专属 | 接口化：定义 Reporter 接口，禅道为第一个实现 |
| `zt.py` 的 ZenTaoClient 依赖 | **全局 Skill 依赖** | DevFlow AI 需自包含禅道客户端，不依赖 `~/.claude/skills/zentao/` |
| 配置 `zentao.allow_finish/allow_close` | 通用配置模式 | 保留配置驱动机制，抽象为 Reporter 配置 |

### 5.4 结论

- `zentao/_shared/client/tasks.py` 应迁移为 DevFlow AI 的 ZenTao TaskProvider。
- `zt.py` 的核心流转逻辑（finish/close/progress）应提取为 Reporter 接口的 ZenTao 实现。
- DevFlow AI **不能依赖** `~/.claude/skills/zentao/` 全局安装，需自带禅道 API 客户端或明确声明为外部依赖。

## 六、release_run.py 归属

### 6.1 当前职责

`scripts/release_run.py`（279 行，10 个函数）实现发版流程编排：

| 子命令 | 职责 |
|--------|------|
| `plan` | 生成发版计划（版本号、Job 清单） |
| `gate` | 发版门禁：QA 必须有真实测试证据（kind ∈ real_api/e2e/unit/integration 且通过），禁止仅代码审查放行 |
| `trigger` | 触发 Jenkins 构建（仅白名单 Job；部署 Job 需 `--decision` 传入 HITL P0 编号） |
| `status` | 轮询构建状态 |
| `report` | 生成发版报告 + 可选 `--writeback` 回写禅道 |

### 6.2 与 Jenkins 回退逻辑的关系

dev 的 `jenkins_run.py` 有额外 4 行：无参数 Job 的 `/build` 回退（dist 没有）。两者配合使用：
- `jenkins_run.py` 负责单次 Job 触发和状态查询
- `release_run.py` 负责完整的发版流程编排（多 Job、门禁、报告、回写）

### 6.3 归属判断

| 能力 | DevFlow AI 归属 | 理由 |
|------|----------------|------|
| Jenkins Job 触发 | CIAdapter Provider — Jenkins 实现 | 通用 CI 触发接口，Jenkins 为一个实现 |
| 发版门禁 | CIAdapter Provider — Gate 机制 | 通用质量门禁，可跨 CI 系统复用 |
| 部署人工确认 | HITL Provider | 部署决策属于人工决策范畴 |
| 构建状态跟踪 | CIAdapter Provider | 通用能力 |
| 发版报告 | Reporter Provider | 通用报告接口 |
| 禅道回写 | Reporter Provider — ZenTao 实现 | 禅道专属 |
| 白名单 Job 约束 | CIAdapter 配置 | 安全约束，保留 |

### 6.4 结论

`release_run.py` 应拆分为：
- **CIAdapter 接口**：Job 触发、状态查询、门禁检查（通用）
- **Jenkins Provider**：Jenkins 特定实现（含无参数 Job 回退）
- **Reporter Provider**：发版报告生成和禅道回写
- **HITL 集成**：部署前人工确认

Jenkins 真实构建和部署的人工确认机制**保留并强化**：部署类 Job 必须经 HITL 决策才能触发。
