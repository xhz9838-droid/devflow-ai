# ADR-DF-018：代码级 Plan Decision Policy

- 状态：已采纳
- 日期：2026-11-21
- 代码：`devflow/planning/policy.py`

## 背景

如果“是否需要问用户”只写在 Prompt 中，模型会过度提问或擅自决定重大风险。DF-018 要求 Decision Policy 成为 Planning Layer 的正式策略。

## 决策

### D1. 四级分类由代码执行

- L0：明确需求，直接纳入计划。
- L1：普通技术实现，Agent 自主决定并记录。
- L2：低风险不确定，调研后采用推荐/现有规范并记录。
- L3：重大决策，才允许进入 Clarification。

### D2. 调研优先

L3 候选必须带 `research` 证据；无证据的问题不会问用户，而是记录 suppressed 和自动决策。

### D3. L3 完整性门槛

L3 必须有：问题、影响说明、2-4 个选项、推荐项（属于选项）。缺少任一项则自动决策或丢弃。

### D4. 控制提问数量

- 默认最多 5 个问题，批量展示。
- 重复问题、已回答问题不再提问。
- 没有 L3 时直接进入 PLAN_READY。
- L0-L2 不生成 Clarification。

### D5. 用户授权边界

用户可授权自主决定普通技术细节。授权只能降级非风险型 L3；包含数据库、API、删除、迁移、权限、安全、兼容、范围、返工、不可逆、生产等风险关键词的 L3 仍然必须询问。

### D6. 变更风险由 Core 分类

Plan Change Request 即使声明 LOW，只要涉及完成节点返工、数据库/API/安全/兼容/范围等风险，Core 重新分类为 MAJOR，进入 HITL。

## 后果

- 问题数量可控，避免“把所有不确定性都交给用户”。
- 重大业务风险不会被“自主决定”掩盖。
- 被抑制的问题和自动决策保留在 Plan decisions/suppressed 中，可审计。
- 策略是启发式规则，仍需在真实项目中持续校准风险关键词和阈值。
